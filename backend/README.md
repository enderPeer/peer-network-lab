# backend — the deterministic Rust engine

The next architecture: deterministic Rust backend, GraphQL API, Postgres as
the graph store. The TS/JS system in `webapp/` remains the reference
implementation and the parity oracle until the last phase strangles it.

## The one rule

**Correct means byte-identical.** Every Rust component that touches the
canonical layer is tested against golden vectors generated by the REAL
JavaScript chain code over real data — the live act log and the live signed
blocks — plus an adversarial battery. There is no second definition of
correct, and no hand-written expected value anywhere in the parity tests.

```
node backend/parity/gen-vectors.mjs   # regenerate after any webapp/chain change
cargo test                            # from backend/
```

The generator imports `webapp/chain/*.mjs`, the built engine bundle
(`webapp/public/peer-engine.mjs` — run `npm run build:social` in webapp/ if
missing), and `webapp/social/replay.cjs`, so the vectors always state what
the running system actually does.

## Crates

- **ender-canonical** — `canonical.mjs` + `merkle.mjs` + the verification
  side of `block.mjs`/`keys.mjs`: canonical JSON encoding (UTF-16 key
  order, ECMA-262 number formatting via `ryu-js`, JSON.stringify escaping),
  SHA-256, quantize with ECMA `Math.round` semantics, domain-separated
  merkle, block digest/hash, Ed25519 signature verification.
- **ender-chain** — `acts.mjs` + the structural half of `chain.mjs`:
  parseMentions, structural/payload act commitments (redaction-invariant),
  and `verify_chain_structure` — the full chain verifier minus the
  epoch-package replay comparison, which lands with the engine port.
- **ender-jsmath** — the JS float kernel: `js_round` (ECMA ties-toward-+∞)
  and vendored pure-Rust translations of V8's fdlibm `exp`/`log`/`tanh`/
  `expm1`/`pow`/`scalbn` (ieee754.cc @ 12.4.254.21 — the V8 inside this
  machine's Node). Proven bit-identical on 19,515 recorded vectors
  (`gen-engine-vectors.mjs`), including real replay call traffic. Platform
  libm and `f64::round/powf/exp/ln` are banned from fold code.
- **ender-engine** — the deterministic fold: port of `social/replay.cjs`
  plus the six engine exports it consumes (`THETA`, `NU`, `RawGraph`,
  `solveStanding`, `evaluateGates`; the retired AttestationLedger is
  omitted). Gate: byte-identical `canonical(epochPackage)` for every close
  in the live and genesis-0 corpora (`tests/vectors/`), with an act-level
  trace bisector (`gen-trace-vectors.mjs`) to name the first diverging
  act. Porting law: `port-notes/CONVENTIONS.md`; structural maps from the
  12-agent survey live in `port-notes/`.

## Traps already caught by the harness

- `serde_json` default float parsing is not correctly rounded; JS
  `JSON.parse` is. The `float_roundtrip` feature is mandatory — without it
  block digests diverge on real data.
- JS sorts object keys by UTF-16 code unit; Rust string order is scalar
  order. They disagree on astral-plane keys.
- JS `Math.round` ties toward +∞ and returns -0 in (-0.5, 0); `f64::round`
  ties away from zero.
- JS `JSON.parse` accepts lone surrogates; `serde_json` refuses them. A
  refusal is a loud error, not a silent hash divergence — acceptable until
  a real act ever carries one (none do today).
