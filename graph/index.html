How to read it

Each node is a concept the parser actually found in a file: a function, a class, a config key, a heading in a document. Each edge says how one reaches the other, and carries a confidence tag.

  • EXTRACTED — written down in the source. server.mjs literally calls validBtcAddress(). 1,988 of the 2,011 edges are this kind. 99% of the graph is quotation, not inference.
  • INFERRED — resolved by graphify across files, where the call is real but the target had to be matched by name. 23 edges, average confidence 0.63. Useful, and the only part you should double-check.

Colours are communities — subsystems found by the Leiden algorithm, then named after their most connected member. Nothing was labelled by a model; the names are the hubs' own filenames.

Connections worth a second look

Edges the tool flagged as surprising — mostly the honest failure mode of name-matching across files.

  • server → validBtcAddress() EXTRACTED webapp/server.mjs → webapp/ads.mjs — real, and worth knowing the ad path validates addresses
  • actCommitments() → act() INFERRED webapp/chain/acts.mjs → agent/agent.mjs — a name collision, not a real call
  • pickWriter() → c() INFERRED webapp/chain/election.mjs → webapp/tests/election.test.ts — matched a one-letter test helper

This is why every edge carries its tag. Two of the three above are wrong, and the graph says so itself rather than presenting all edges as equal.

No import cycles were detected anywhere in the tree.

Rebuild it yourself

Nothing here is a build artifact you have to trust. The parse is deterministic and local — same commit in, same graph out.

pip install graphifyy
graphify update .        # writes graphify-out/graph.html, graph.json, GRAPH_REPORT.md
graphify god-nodes       # the table above
graphify path "verifyChain" "applyActInner"
